# 常见问题（FAQ）

本文汇总 `vt-boot-ui` 在安装、启动、联调与构建过程中的高频问题与排查思路。

## 一、安装与启动

### Q1：`npm install` 很慢或失败

**原因**：网络访问默认源受限。

**处理**：项目 `.npmrc` 已指向 `registry.npmmirror.com`。如仍失败，检查网络，或临时改用 `npm install --registry=https://registry.npmjs.org`。

### Q2：启动报 Node 版本过低

**原因**：`Vite 8` 依赖较新的 Node。

**处理**：确认 `node -v` 为 **20 及以上**（推荐 LTS），升级后重新 `npm install`。

### Q3：端口 `5180` 被占用

**原因**：已有其他进程占用开发端口。

**处理**：修改 `vite.config.js` 的 `server.port`，或结束占用进程后重启 `npm run dev`。

## 二、联调相关

### Q4：登录后侧边栏为空 / 只有工作台

**原因**：`/api/auth/menus` 未返回菜单，或当前角色未被授权任何菜单。

**处理**：确认 `t_menu` 有数据、`t_role_menu` 已授权给当前用户的角色；用管理员登录后在「角色管理」勾选菜单并保存，重新登录生效。若接口本身 500，检查 `t_role` / `t_menu` / `t_user_role` / `t_role_menu` 四张表是否已建（执行 `db/rbac-mysql.sql`）。

### Q5：点击菜单进入空白页 / 控制台提示找不到组件

**原因**：后端菜单的 `component` 值与前端注册表不一致。

**处理**：把菜单 `component` 改成 `src/router/components.ts` 中已注册的键（如 `system/user/UserList`）；新增页面需先在该文件中注册。

### Q6：接口返回「无权限, 缺少权限 [xxx]」

**原因**：当前账号角色的菜单授权中没有对应权限码。

**处理**：管理员在「角色管理」为该角色勾选对应页面/按钮并保存；权限有本地缓存（默认 5 分钟），也可重新登录立即生效。

### Q7：为什么不是 HTTP 403？

**说明**：后端 `SecurityUtils.requirePermission` 抛出的是业务异常，统一返回 **HTTP 200 + `success=false` + `msg`**；请求拦截器会弹出提示。真正的路由级越权由前端守卫跳转 `/403` 页面。

### Q8：时间字段显示异常（如 `[2026,11,20,9,0,0]`）

**说明**：说明后端按 Jackson 数组形态序列化时间。`formatDateTime` / `toDateTimeString` 已兼容字符串（ISO 或空格分隔）、数组与时间戳四种形态；若仍异常，请贴出接口响应体进一步排查。

### Q9：修改角色/菜单后没有立即生效

**原因**：菜单与权限在登录后拉取，后端权限快照有本地缓存（默认 300 秒）。

**处理**：退出后重新登录可立即刷新；必要时重启后端清空缓存。


### Q10：接口 404

**原因**：后端未启动，或 `backend` 地址不正确。

**处理**：确认后端示例应用在 `9086` 运行；核对 `vite.config.js` 中的 `backend` 常量是否为后端实际地址，修改后重启开发服务。接口清单见 [接口说明](./api.md)。

### Q11：接口 401 / 登录状态失效

**原因**：未登录、令牌过期，或后端 `sa-token` 拦截了未放开的路径。

**处理**：
- **认证与系统管理**（`/api/auth/**`、`/api/system/**`）需要登录令牌。前端会自动携带 `Authorization` 头，401 时用刷新令牌静默续期；续期失败会清理凭证并跳回登录页，重新登录即可。
- **任务调度**（`/api/task/**`）在示例工程中是放开鉴权的；若后端已收紧，需要登录后再访问，或调整 `sa-token.yaml` 的 `exclude-path-patterns`。
- 刷新令牌失效（超过 7 天或已被撤销）时只能重新登录，属正常安全策略。

### Q12：登录提示「账号不存在 / 密码错误 / 账号已被锁定」

**原因**：账号密码不正确，或连续 5 次密码错误触发 15 分钟锁定。

**处理**：核对 `sys_user` 表中的账号；等待锁定时间结束后重试，或由管理员在「用户管理」中重置密码。

### Q13：出现跨域（CORS）错误

**原因**：开发期应经 Vite 代理访问，若绕过代理直连后端可能触发跨域。

**处理**：开发期保持 `request` 的 `baseURL` 为空、请求走 `/api` 前缀由代理转发；生产期采用同源反向代理。

### Q14：详情页没有数据

**原因**：详情页从路由参数取数，直接访问缺少参数。

**处理**：
- 任务详情需携带 `name`（及可选 `group`）：`/task/job/detail?name=demoJob&group=DEFAULT`。
- 日志详情需携带路径参数 `id`：`/task/log/detail/1`。
- 正常从列表点击「详情」进入会自动带上参数。

## 三、构建与产物

### Q15：构建后接口全部 404 / 跨域

**原因**：生产环境未配置 `/api` 反向代理。

**处理**：由 Nginx 或网关把 `/api` 反向代理到后端，前端静态资源同源部署，无需额外跨域配置。详见 [配置说明](./configuration.md) 第七节。

### Q16：没有生成 `.gz` 文件

**原因**：`vite-plugin-compression` 仅压缩大于 `10KB` 的产物。

**处理**：小体积产物不生成 `.gz` 属正常现象；如需调整阈值，修改 `vite.config.js` 中的 `threshold`。部署时可开启 Nginx `gzip_static` 复用预压缩产物。

### Q17：构建出现 chunk 体积告警

**原因**：`build.chunkSizeWarningLimit` 默认 `1500`（KB），超出即告警。

**处理**：已按 `vue-vendor` / `element-plus` / `utils` 手动分包；若仍告警，可评估按需引入 Element Plus 组件进一步瘦身。

### Q18：`npm run build` 报类型错误

**原因**：工程开启 `strict`、`noUnusedLocals`、`noUnusedParameters`。

**处理**：按报错清理未使用变量 / 参数，补全类型；提交前确保类型检查通过。

## 四、使用相关

### Q19：任务参数（JSON）保存失败

**原因**：任务参数输入框内容不是合法 JSON。

**处理**：新增 / 编辑弹窗会将参数文本 `JSON.parse` 校验，非法时提示「任务参数不是合法的 JSON」。请填写形如 `{"key":"value"}` 的 JSON 对象，留空表示无参数。

### Q20：执行日志「耗时」显示为 `-`

**原因**：`durationMs` 为空（任务尚未结束或未记录耗时）。

**处理**：属于正常展示；`formatDuration` 对空值返回 `-`。

### Q21：日志详情页异常信息看不清

**原因**：异常信息用专门的红色代码块展示。

**处理**：属正常样式；异常信息位于「异常信息」区块，红底浅字，便于定位错误。

### Q22：登录后看不到「系统管理」菜单

见 [Q4](#q4登录后侧边栏为空--只有工作台)：菜单由 `/api/auth/menus` 与角色授权共同决定，权限不足时菜单与页面都会被隐藏或拦截。

### Q23：修改用户密码后仍显示旧状态

**原因**：用户列表数据在操作后会自动重新加载；若浏览器缓存了旧页面可手动刷新。

**处理**：点击顶栏刷新按钮或浏览器刷新即可；启停开关切换失败会自动回滚显示。

## 五、反馈

如遇本文未覆盖的问题，请优先检查后端连通性（`/api/auth/**`、`/api/system/**`、`/api/task/**`）、代理配置（`vite.config.js` 的 `backend`）与浏览器控制台报错信息。
